# DroidScout

**Сканер локальной сети для поиска Android-устройств** — телефонов, планшетов, TV-приставок и медиаплееров. GUI-приложение на Python (PySide6/Qt) с тёмной и светлой темами, двуязычным интерфейсом (RU/EN), историей сканирований и самообновлением с GitHub.

*English version: [README.en.md](README.en.md)*

---

## Установка

### В одну строку — публичный репозиторий, без токена

**Windows (PowerShell):**

```powershell
irm https://raw.githubusercontent.com/teliy/droidscout/main/install.ps1 | iex
```

**Linux / macOS (bash):**

```bash
curl -fsSL https://raw.githubusercontent.com/teliy/droidscout/main/install.sh | bash
```

Установщик спросит каталог установки, проверит Python 3.9+ (при отсутствии предложит установить), сам скачает репозиторий, **создаст venv**, поставит все зависимости и создаст ярлыки:

- Windows: ярлык на рабочем столе + `DroidScout.cmd`;
- Linux/macOS: команда `droidscout` в `~/.local/bin` + запись в меню приложений.

> Свой форк? Замените `teliy` на ваш GitHub-логин (или запустите `scripts/publish_github.*` — он подставит логин сам).

### Если репозиторий приватный (с токеном)

GitHub отдаёт файлы **приватного** репозитория только по токену — обычная ссылка `raw.githubusercontent.com` вернёт **404 Not Found**. В этом случае:

**Шаг 1.** Создайте fine-grained токен: <https://github.com/settings/personal-access-tokens/new>

- *Repository access* → *Only select repositories* → `droidscout`;
- *Permissions → Repository → Contents* → **Read-only** (Metadata подставится автоматически);
- срок действия — на ваш выбор. Токен хранится только на вашем компьютере.

**Шаг 2.** Скопируйте блок целиком и вставьте в консоль — он спросит логин и токен:

**Windows (PowerShell):**

```powershell
& { $o = Read-Host "Логин GitHub"
    $s = Read-Host "Токен GitHub" -AsSecureString
    $t = [Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR($s))
    $env:DS_OWNER = $o
    $env:DS_TOKEN = $t
    $f = Join-Path $env:TEMP "droidscout-install.ps1"
    Invoke-WebRequest -UseBasicParsing -Headers @{ Authorization = "token $t" } -Uri "https://raw.githubusercontent.com/$o/droidscout/main/install.ps1" -OutFile $f
    & $f
    Remove-Item Env:DS_TOKEN, Env:DS_OWNER -ErrorAction SilentlyContinue
    Remove-Item $f -ErrorAction SilentlyContinue }
```

**Linux / macOS (bash):**

```bash
read -rp "Логин GitHub: " DS_OWNER; read -rsp "Токен GitHub (скрытно): " DS_TOKEN; echo; \
export DS_OWNER DS_TOKEN; \
curl -fsSL -H "Authorization: token $DS_TOKEN" "https://raw.githubusercontent.com/$DS_OWNER/droidscout/main/install.sh" | bash; \
unset DS_OWNER DS_TOKEN
```

Установщик спросит каталог установки, скачает репозиторий по токену, создаст venv,
поставит зависимости и **сохранит токен в настройки приложения** — автообновления будут
работать сразу. Сменить или удалить токен можно позже: приложение → Настройки → Репозиторий.

## Что умеет

- **Поиск всех живых хостов** в подсети (ICMP-опрос, до 65 000 адресов; при заблокированном ICMP — автоматический TCP-опрос всех адресов).
- **Честная таблица без мусора**: хост, не ответивший ни на ping, ни показавший ни одного порта/MAC/имени, в таблицу не попадает; откликнувшиеся только на ping показываются приглушённо серым и не помечаются «новыми» — зелёная подсветка достаётся только настоящим новинкам с данными.
- **TTL из ping-ответа** в карточке устройства с определением класса ОС (64 — Linux/IoT, 128 — Windows, 255 — сетевое оборудование).
- **Кнопка «Все порты»** у карточки: скан 1–65535 с прогрессом, скоростью и ETA; распознавание сервисов (HTTP-заголовки, TLS-сертификаты, SSH/FTP-баннеры, RTSP, Redis, telnet, Python-REPL…), показ сырых ответов (текст + hex) с контекстом устройства — журнал опроса всегда содержит IP, MAC, имя и производителя; молчащие порты получают контрольную допробу (медленные REPL-консоли отвечают с задержкой); UDP-пробы, сохранение отчёта.
- **Наковырывает сам**: ADB-порт (5555) опознаётся по рукопожатию CNXN без авторизации — модель, имя и кодовое устройство Android попадают в таблицу и карточку; найденная Python/MicroPython-консоль автоматически проходит полный REPL-опрос — прошивка и чип (`os.uname()`), содержимое файловой системы (`os.listdir('/')` и `os.listdir('/flash')` — скрипты производителя и конфиги), исходник `main.py` (что модуль делает при загрузке), серийник и частота (`machine.unique_id()/freq()`), сетевые настройки (`network.WLAN(0).ifconfig()`) и свободная память — только читающие print-запросы, каждая завёрнута в `exec("try:…except:…")` и не рвёт сессию; транскрипт и блок «Что выяснили» — в сыром ответе, отчёте и признаках карточки. Консоли-самозванцы (псевдо-REPL вида «Bad command …» у модулей вроде Shenzhen iComm) опознаются первым вопросом: вместо восьми бесполезных исходников уходят читающие пробы help/?/version/… и словарь из ~60 типовых команд (sysinfo, get, ifconfig, ls, at+gmr, …); живые команды с их ответами (список команд, версия прошивки, usage-подсказки) попадают в факт «Console: …», а если словарь отвергнут целиком — «Console dict: N probed, all rejected».
- **Wake-on-LAN** — включение устройства по сети из карточки.
- **Определение Android-устройств** с оценкой уверенности 0–100 % по совокупности признаков:
  - открытый ADB по сети (порт 5555) и ADB TLS;
  - mDNS-службы: Google Cast, Android TV Remote, AirPlay;
  - SSDP/UPnP-описания (производитель, модель, MediaRenderer);
  - HTTP-баннеры с упоминанием Android/embedded Linux;
  - производитель по MAC-адресу из базы IEEE (40 000+ префиксов: Samsung, Xiaomi, Huawei, Google, TCL, Amlogic и др.);
  - имена хостов вида `android-*`, модели Fire TV (`AFT*`).
- **Полная карточка устройства**: IP, MAC, производитель, имя хоста, тип (телефон/планшет, Android TV/приставка, медиаплеер…), модель, открытые порты, службы, признаки.
- **Телефон по Wi-Fi без кабеля** (Android 11+): кнопка «Телефон Wi-Fi» — сопряжение по «Отладке по Wi-Fi» с кодом из экрана телефона и подключение на порт adb. Протокол воспроизведён по исходникам ADB (SPAKE2 на curve25519 + TLS 1.3 с клиентским сертификатом + AES-GCM), открытый ключ adb сохраняется на телефоне — дальше обычный ADB-протокол внутри TLS: опрос, приложения, пульт, скриншоты, файлы. Порт берётся из реестра и переживает перезапуск приложения; после перезагрузки телефона достаточно повторить «Подключить» с свежим портом.
- **ADB-детали** (опционально): модель, бренд, версия Android, SDK, серийный номер — работает без установленного adb благодаря встроенному клиенту.
- **ADB-инструментарий** (кнопка «ADB: инструментарий» у карточки устройства) — всё управление через встроенный клиент, без внешнего adb:
  - **Инфо** — батарея, оперативная память, диск, экран, время работы, IP устройства; перезагрузка (обычная / Recovery / Bootloader);
  - **Железо** — полный опрос CPU/SoC с расшифровкой: точная модель чипа (sun50iw9p1 → Allwinner H616/H313/H618/H700, gxl → Amlogic S905X, rk3328 → Rockchip RK3328 — по device-tree, ro.board.platform, ro.hardware и ro.soc.model), ядра по ARM-кодам (0xd03 → Cortex-A53) с частотами и governor, GPU с архитектурой (Mali-G31 → Bifrost), RAM и eMMC-чип с ёмкостью, разделы, дисплей с частотой обновления, батарея, датчики температуры, сетевые интерфейсы, ядро, модель платы и аппаратные возможности; итог — «Расшифровка» одной строкой и копирование отчёта в буфер;
  - **Приложения** — список (сторонние / системные / все), запуск, остановка, удаление, отключение, очистка данных, информация о версии, установка APK с компьютера (файл передаётся по ADB sync). Список снимается цепочкой попыток с разными флагами `pm list packages` (-3 → -f -3 → -f с фильтром по /data): на прошивках, где `pm` отвергает флаги или молчит, список всё равно находится, а каждый сырой ответ виден в журнале;
  - **Пульт** — D-pad, OK, Home, Back, Menu, громкость, mute, play/pause, питание — управление TV-приставкой мышью; отправка текста;
  - **Скриншот** — снимок экрана устройства в один клик (PNG), сохранение в файл;
  - **Консоль** — произвольные shell-команды с историей (стрелки вверх/вниз);
  - **Настройки** — режим разработчика одним кликом: флаг `development_settings_enabled` (то, чем прошивки на манер titan-p1 прячут меню «Для разработчиков», когда 7 нажатий на «Номер сборки» ничего не дают): показать текущее значение, включить/выключить с контрольным чтением, открыть меню на экране устройства (`am start`); плюс произвольные `settings get/put` в разделах global/secure/system — значение экранируется, поэтому «Too many arguments» не бывает;
  - **Логкат** — последние N строк с фильтром по уровню (V/D/I/W/E), очистка буфера, сохранение;
  - **Журнал** — файловый журнал действий и ответов (journal.log в каталоге настроек): каждая shell-команда с временем выполнения и ответом устройства (длинные ответы обрезаются с пометкой размера), ошибки соединений с типом исключения, отметки нажатых кнопок; просмотр, копирование одним кликом и открытие файла прямо из диалога — приложите журнал к сообщению о проблеме, по нему видно, где именно сбой;
  - **Оценка безопасности** — цветной вердикт риска: возраст патча безопасности, «поддельная» прошивка (версия Android не совпадает с SDK), adbd от root, наличие su, отключённая авторизация ADB (ro.adb.secure=0) — с рекомендациями.
- **Вкладка «Монитор»** — живые показатели выбранного устройства с автообновлением 2/5/10 с: CPU (ядра и частоты), RAM, батарея, температуры; после 3 ошибок связь ставится на авто-паузу.
- **Вкладка «Действия»** — тумблеры устройства: Wi-Fi, мобильные данные, Bluetooth, режим полёта, гасить/будить экран, stay-on, яркость 5–255 с чтением состояния.
- **Встроенный ADB-клиент** (pure Python): DroidScout сам подключается к adbd устройства по сети (порт 5555) — Platform-Tools устанавливать не нужно. RSA-ключи совместимы с официальным adb: используется `~/.android/adbkey`, поэтому уже авторизованные устройства не потребуют повторного подтверждения. Опрос выполняется одним запросом `getprop` (без запуска внешних процессов и консольных окон в Windows). Бинарные сервисы (`exec:`, `sync:`) — скриншоты и передача файлов без искажений.
- **Автоустановка Platform-Tools**: если внешний adb всё же нужен (USB-устройства, TLS-отладка), приложение предложит скачать официальный архив с сервера Google и распакует его автоматически (Настройки → ADB).
- **История сканирований** (SQLite) и **подсветка новых устройств** (только тех, у кого есть MAC/порты/имена).
- **Экспорт отчёта** в CSV (Excel-совместимый) и JSON.
- **Темы**: тёмная и светлая, переключение на лету. **Языки**: русский и английский, автоопределение по локали.
- **Самообновление**: приложение проверяет GitHub Releases при запуске (отключается в настройках) и по кнопке, скачивает новую версию, устанавливает её поверх (venv и история не затрагиваются) и предлагает перезапуск.

## Запуск без установки

```bash
git clone https://github.com/teliy/droidscout
cd droidscout
python -m venv venv
venv/bin/pip install -r requirements.txt    # Windows: venv\Scripts\pip
venv/bin/python droidscout.py               # Windows: venv\Scripts\python droidscout.py
```

## Обновления

- Кнопка **«Проверить обновления»** или автоматическая проверка при старте.
- Репозиторий **публичный** — токен не нужен: приложение само скачивает новую версию с GitHub Releases.
- Если работаете со своим **приватным** форком, приложению нужен GitHub-токен (fine-grained, права Contents: Read достаточно): установщик сохраняет его автоматически, либо укажите вручную в «Настройках» — иначе API вернёт 404.

## Как это работает

| Этап | Метод | Что даёт |
|---|---|---|
| 1 | ICMP ping-опрос подсети | список живых хостов |
| 2 | Чтение ARP-таблицы ОС | MAC-адреса и производители |
| 3 | TCP-сканирование 25 портов | ADB, Cast, HTTP, SSH, UPnP и др. |
| 4 | mDNS (zeroconf) | Google Cast, Android TV Remote, ADB TLS, AirPlay + модели |
| 5 | SSDP/UPnP | производитель, модель, MediaRenderer |
| 6 | HTTP GET | баннеры `Server:`, `<title>` |
| 7 | Обратный DNS | имена хостов |
| 8 | Эвристика | тип устройства и вердикт «Android» с уверенностью |

Права администратора не требуются: используются только системные `ping`, ARP-таблица и обычные TCP-подключения.

## Публикация приватного репозитория

```bash
# 1. Установите GitHub CLI и войдите: gh auth login
# 2. Из корня проекта:
./scripts/publish_github.sh ВАШ_ЛОГИН          # Linux/macOS
powershell -File scripts\publish_github.ps1 -Login ВАШ_ЛОГИН   # Windows
```

Скрипт создаст приватный репозиторий `droidscout`, запушит код, подставит логин во все
установщики, создаст релиз `v1.0.0` (чтобы автообновления сразу работали) и напечатает
готовые команды установки и создания токена.

```
droidscout/
```

## Известные ограничения

- Рандомизация MAC в современных телефонах может скрывать производителя — в этом случае Android определяется по службам (Cast/ADB/TLS).
- ADB-опрос работает только если на устройстве включена «Отладка по USB» и пользователь разрешил подключение. При первом подключении на экране устройства появится диалог «Разрешить отладку по USB» — подтвердите его (лучше с галочкой «Всегда разрешать»). Встроенный клиент использует те же ключи, что и официальный adb, поэтому повторное подтверждение для уже авторизованных устройств не требуется.
- Windows SmartScreen может предупредить о запуске скачанного из интернета скрипта — это нормально для PowerShell-установщиков.
- Для сканирования нескольких /24-подсетей используйте выбор «Все сети».
